# Cost accounting

This directory regenerates every cost number in the paper from the raw timing logs and token counts
in `data/cost/`, and compares each one with the number the paper prints. Everything runs on CPU in
seconds, except `pool_token_count.py`, which re-tokenizes the SFT pool in about two minutes.

```bash
python -m cost.table1                        # Table 1 and all of Appendix A.4; exits 1 on a mismatch
```

Run the scripts from the repository root. They need the `lesser` package and its dependencies
(`pip install -e .`); `pool_token_count.py` also needs the `sft` extra. Shared constants (pool size,
SFT budgets, Llama-2 vocabulary and hidden size) come from `sft/common.py`, the projection sizes from
`lesser.SFT_PAPER` and `lesser.RL_PAPER`, and the pool encoding of `pool_token_count.py` from
`sft/nayak_data.py`.

## Commands

| Command | What it regenerates |
|---|---|
| `python -m cost.table1` | Table 1 and every number below; verifies `data/cost/MANIFEST.json` first |
| `python -m cost.sft_flops` | Appendix A.4 "SFT extraction FLOPs", Tables 5 and 6 |
| `python -m cost.timing_sft.parse_logs` | Appendix A.4 "SFT extraction wall clock", Table 1(a) |
| `python -m cost.rl_flops` | Appendix A.4 "RL scoring FLOPs and storage", Table 7, feature sizes of Table 1(b) |
| `python -m cost.timing_rl.parse_logs` | Appendix A.4 "RL scoring wall clock", Table 1(b) |
| `python -m cost.timing_grace.parse_timing` | Appendix A.4 "GRACE extraction wall clock", Table 8 |
| `python -m cost.pool_token_count` | T and T_r of Table 5; recomputes `data/cost/pool_token_count.json` and fails on any difference |

Each script prints its section, then one line per paper number. `OK` means the regenerated value,
rounded the way the paper rounds it, equals the printed string; `KNOWN` marks the one documented
paper-side discrepancy below; `DIFF` marks anything else and makes the script exit with status 1.

Options:

- `--paper-dir PATH` also checks that every expected string occurs in its LaTeX context in a
  checkout of the paper source. At paper revision df9fc85 all 77 snippets are found.
- `table1 --latex` prints the LaTeX rows of Tables 1 and 5 to 8 from the regenerated values.
- `table1 --json-out FILE` writes all regenerated numbers and the check results.
- `pool_token_count --out FILE` writes the counts instead of comparing. Set `HF_HUB_OFFLINE=1
  HF_DATASETS_OFFLINE=1` to use a local Hugging Face cache; dataset and tokenizer revisions are pinned.

Paper numbering below is that of the paper source at revision df9fc85 (the same as the submitted 24f4b57).

The scripts also print numbers that the compiled paper does not state: the exact (unprojected)
output-layer RL feature, 3.55e9 FLOPs per scored token (2.6x), 29.1 min per round (2.2x) and
933 MB per problem; released LESS at projection interval 16, 2,204 s per checkpoint on the prefix
(15.3x for four checkpoints); four-checkpoint LESS without its gradient projection, 8.24x; and the
projection's share of LESS's FLOPs, 15.3%.

## Conventions

- FLOPs: 2P per token for a forward pass and 6P for a forward and backward pass, plus the explicit
  terms of Appendix A.4 (LoRA weight-gradient terms, LESS's gradient projection, LESSER's two-sided
  projection). Softmax, normalization, dot products and data movement are not counted.
- The extraction-plus-training model of Table 6 adds 6 P T_train with two epochs and selected
  examples as long as the pool mean. Its LESSER side uses F_LESSER, as the computation behind the
  paper did; the paper text writes 2PT_pool, and the difference, 0.01%, changes no printed digit.
- Wall clock: whole-process times, from model and data loading to writing the features. The pool
  figures scale the prefix time linearly in the number of examples; LESS is counted once per
  checkpoint, four times in total.
- Rounding: half up, applied to the exact rational value. kB, MB and GB are decimal units; peak
  memory is in GiB.

## Timing jobs

Each job ran on one NVIDIA A100 80GB PCIe, with every compared method in the same job.

| Job | What ran | Raw data |
|---|---|---|
| SFT timing | Llama-2-7B, first 10,000 pool examples, bf16: LESSER, then released LESS (`representation/less/compute_less_embeds.py` of dcml-lab/targeted-instruction-selection at 8ff397a, unchanged) at checkpoint 316 with the CUDA projector at projection interval 8 (the paper's number) and 16 | `data/cost/timing_sft/` |
| RL timing | Qwen2.5-Math-1.5B-Instruct, the 81,920 candidate and 3,200 query responses of one selection round, released GradAlign scorer three times: projected LESSER feature, exact LESSER feature, full gradients | `data/cost/timing_rl/` |
| GRACE timing | GRACE feature extraction, 32 random responses per teacher, one at a time, fp32 student, 512-dimensional CUDA projector, full gradients against LESSER, three settings | `data/cost/timing_grace/` |

The timed LESSER SFT extractor also computes the hidden-state and residual-only diagnostic features
in the same pass, so its time is an upper bound for LESSER.

## Data and provenance

`data/cost/MANIFEST.json` lists every file in `data/cost/` with its size, sha256, source and a note,
and under `referenced_not_shipped` the code and data the timing jobs used that are not included
(the timed extractor and scorer code with the sha256 recorded in the job logs, the LESS warmup
checkpoint, the 681 MB of re-scored RL responses and the 12.9 MB GRACE timing inputs).
`python -m cost.table1` verifies every size and sha256 before computing.

| File | Content |
|---|---|
| `pool_token_count.json`, `.log` | T, T_r, mean length and truncation count of the 197,196-example pool for the Llama-2 and Llama-3.2 tokenizers |
| `sft_flops.json` | the SFT FLOP computation behind the paper; `sft_flops` reproduces it to 1e-12 |
| `timing_sft/` | `timing.log` (stage times, GPU, sha256 of the timed code), `lesser_prefix.log`, `less_pi8.log`, `less_pi16.log` |
| `timing_rl/` | `timing.log`, `prodsk.log`, `prod.log`, `sim.log`, `agreement.json` (ranking agreement between the variants) |
| `timing_grace/` | `timing.json` (per-response times, peak memory, correctness cosines), `grace_timing.log` |
