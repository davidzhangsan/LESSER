# GRACE teacher ranking with LESSER features

GRACE (Panigrahi et al., *In Good GRACES*, ICLR 2026) ranks candidate distillation teachers by the
student's gradients on each teacher's responses. The LESSER paper replaces these full-gradient
features with LESSER features, the exact output-layer gradient from one forward pass, and keeps
the rest of the released pipeline: teachers, prompts, responses, the 512-dimensional random
projection, and the scoring rule. This directory regenerates every GRACE result of the paper.

## Paper results and commands

Tier 1 needs only this repository and NumPy. Tier 2 re-scores the stored feature banks on a CPU;
the banks (415 MiB) are not distributed with this release.
Tier 3 recomputes the banks on GPUs with the patched GRACE code in
[`third_party/GRACE`](../third_party/GRACE/README.md).

## Commands

Tier 1 (a few seconds):

```bash
python grace/tables.py
```

Tier 2 (CPU, a few minutes). The GRACE scorer is not modified by the patch, so a plain upstream
checkout suffices; `score.py` refuses a scorer file that differs from the released one.

```bash
git clone https://github.com/abhishekpanigrahi1996/GRACE.git grace_upstream
git -C grace_upstream checkout 64fc99a10049f79abe05e2be638a178b448985d0
# place the feature banks under artifacts/grace/features/<setting>/
for s in gsm8k_llama1b gsm8k_olmo1b math_llama3b; do
  python grace/score.py grace --setting $s --features-dir artifacts/grace/features/$s \
      --grace-repo grace_upstream --out outputs/grace/scores_$s.json --check
done
python grace/score.py bank-stats --features-dir artifacts/grace/features/gsm8k_llama1b \
    --out outputs/grace/bank_stats_gsm8k_llama1b.json --check
python grace/tables.py --data-dir outputs/grace
```

`--check` compares each new score with `data/grace` and raises on a difference. On a busy machine,
cap the BLAS threads (for example `OMP_NUM_THREADS=4`).

Tier 3 (GPU). Set up the patched checkout and its environment as in
[`third_party/GRACE/README.md`](../third_party/GRACE/README.md), then:

```bash
export GRACE_DIR=/path/to/patched/GRACE          # required
export GEN_PY=/path/to/vllm/env/bin/python        # generation only
export FEATURES_DIR=$PWD/artifacts/grace/features # default
bash grace/featurize.sh gsm8k_llama1b subset      # checks the sha256 of the prompt subset
bash grace/featurize.sh gsm8k_llama1b generate    # or use stored responses, see below
bash grace/featurize.sh gsm8k_llama1b features
bash grace/featurize.sh gsm8k_olmo1b features     # uses the gsm8k_llama1b responses
bash grace/featurize.sh math_llama3b subset
bash grace/featurize.sh math_llama3b generate
bash grace/featurize.sh math_llama3b features     # full gradients need a GPU with about 50 GiB
```

The pipeline sets no sampling seed, and batching, hardware, and the vLLM version can change sampled
responses, so regenerated responses are not expected to match the stored ones. The stored banks
were computed from stored teacher responses, which are not distributed; responses copied into
`$GRACE_DIR/data/gsm8k_synthetic/` and `$GRACE_DIR/data/math_synthetic/` replace the `generate`
stage. Pass teacher short names after the stage to restrict it, for
example `bash grace/featurize.sh gsm8k_llama1b features Phi-4`.

## Protocol of the paper runs

Prompts.
- GSM8K: the 7,473 problems of upstream `data/gsm8k/train.jsonl`. MATH: the 7,500 problems of
  upstream `data/math/train.jsonl`.
- The file order is shuffled with `random.Random(42)`, the first 512 problems are kept in shuffled
  order (`scripts/generate_subset.py`, `scripts/math_subset_512.py`). This is the problem selection
  of upstream `tokenize_data.py --subsample-questions 512`, the default of upstream
  `scripts/grace.sh`, so generating only for these 512 problems gives the same scored rows as
  generating for the whole training set.

Responses.
- vLLM with the teacher's chat template. The user turn is the upstream prompt
  `Please reason step by step and put your final answer within \boxed{{}}.` (with the doubled braces
  of upstream `generate_responses.py`), a blank line, and the problem. Temperature 0.6, top-p 1.0,
  at most 4,096 new tokens. The pipeline sets no sampling seed, so vLLM's engine default applies.
- **GSM8K: 16 responses per prompt, of which GRACE scores 4.** Each teacher generated 16 responses
  per prompt, the upstream default of `scripts/generate.sh`. Upstream `tokenize_data.py
  --subsample-responses 4`, the default of `scripts/grace.sh`, shuffles the 16 responses of the
  prompt at position `i` of the subset with `random.Random(13 * i + 13)` and keeps the first four.
  Checked against the stored data: for all 14 teachers, the 2,048 scored rows are exactly these
  responses.
- MATH: 4 responses per prompt, generated directly. The same subsample step then only reorders the
  four responses of each prompt, and the GRACE score does not depend on that order.
- OLMo-2-1B student: the GSM8K responses of the ten original teachers with the same 4-of-16
  subsample.
- Appendix A.3 says that each teacher "generates four responses to each of 512 shared prompts".
  This holds for MATH. For GSM8K each teacher generated 16 responses per prompt and GRACE used four of
  them per prompt.
- vLLM version and memory caps. All MATH generations used vLLM 0.11.0 with `--max_model_len 4096
  --max_num_seqs 64`. GSM8K:

  | teachers | vLLM | extra arguments |
  |---|---|---|
  | Qwen2.5-Math-1.5B-Instruct, Qwen2.5-1.5B-Instruct, Qwen2.5-Math-7B-Instruct, Qwen2.5-7B-Instruct | 0.11.0 | none |
  | Qwen2.5-3B-Instruct, Llama-3.2-3B-Instruct, Gemma-2-2b-it, Llama-3.1-8B-Instruct | 0.11.0 | `--max_model_len 8192 --max_num_seqs 64` |
  | OLMo-2-7B-Instruct | 0.11.0 | `--max_model_len 4096 --max_num_seqs 64` |
  | Gemma-2-9b-it | 0.11.0 | `--max_model_len 4096 --max_num_seqs 32 --gpu_memory_utilization 0.88` |
  | Qwen2.5-14B-Instruct, Phi-4, OLMo-2-13B-Instruct, Gemma-2-27b-it | 0.16.0 | none |

  The roster files `data/grace/scores_*.json` record these per teacher, and `featurize.sh` passes
  them on.

Tokenization.
- Upstream `tokenize_data.py`: `### Problem:\n{problem}\n\n### Solution:\n`, then the response and the
  student tokenizer's EOS token, without special tokens at the start. Prompt positions have label
  -100. Student tokenizers: `meta-llama/Llama-3.2-1B` (row 1), `allenai/OLMo-2-0425-1B` (row 2),
  `meta-llama/Llama-3.2-3B` (row 3).
- Row 2 truncates sequences at 4,096 tokens, the context length of OLMo-2: 13 of 20,480 rows
  (3 of Llama-3.2-3B-Instruct, 8 of Qwen2.5-Math-7B-Instruct, 2 of Llama-3.1-8B-Instruct).

Features, one response at a time with the student in float32.
- Full gradients, as released: the backward pass of the student's mean cross-entropy over the
  response tokens; the gradients of all parameters, concatenated (1.24, 1.48, and 3.21 billion
  entries for the three students); a TRAK `CudaProjector` (Rademacher, seed 0, 512 dimensions); the
  result divided by the square root of the number of entries. Sequences longer than 2,560 tokens
  (2,048 for OLMo-2-1B) use gradient checkpointing, which changes the projected gradient by about
  5e-6 in relative L2.
- LESSER: from a forward pass without backward,
  `G = (1/n) sum_t (softmax(z_t) - e_{y_t}) h_t^T` over the `n` supervised positions, where `z_t` are
  the logits and `h_t` the final hidden state that produces them. `G` is flattened (vocabulary size
  times hidden size entries), projected with a `CudaProjector` of the same kind (Rademacher, seed 0,
  512 dimensions), and divided by the square root of its length.
  `lesser.output_layer_gradient(h, r, mean=True)` with `h, r` from `lesser.token_factors_from_logits`
  computes the same `G`. The Llama students tie input
  and output embeddings, so `G` is the output-layer part of the shared matrix's gradient; OLMo-2-1B
  does not, and there `G` equals the gradient of `lm_head.weight` (checked with autograd in the
  paper run).
- The SM count passed to fast_jl is 128 for all banks (see `third_party/GRACE/README.md`).
- Hardware: RTX 4090 for all banks except the MATH full gradients, which ran on an RTX PRO 6000
  with transformers 5.3.0 and torch 2.9.1.

Scores.
- Upstream `GRACE_computation.grace` with the defaults of upstream `scripts/grace.sh`: dimension 512,
  4 responses per prompt, 10 seeded splits of the prompts into 461 training and 51 test prompts,
  eigenvalue smoothing 1e-3, training rows normalized, test rows raw. Per split the score is
  `trace(H^-1 T)`, with `H` the smoothed second-moment matrix of the training features and `T` that
  of the test features; the teacher's score is the mean over splits. Lower is better, so the
  top-ranked teacher has the lowest score.
- Table 12 reports the Spearman correlation over all teachers between the full-gradient and LESSER
  scores, and the top-ranked teacher under full gradients; `tables.py` also checks that LESSER ranks
  the same teacher first.

Appendix F.4 statistics (setting of row 1).
- Per teacher and feature type, the 2,048 rows are normalized. From the eigenvalues `lambda` of
  `X^T X / 2048`, which sum to 1: spectral entropy `-sum lambda log lambda`, effective rank
  `1 / sum lambda^2`, `sum sqrt(lambda)`, and the largest eigenvalue. From the cosine similarities of
  all 2,096,128 pairs of responses: mean, 95th percentile, fraction above 0.8, and skewness. The
  central responses are the 64 rows with the largest cosine similarity to the mean direction.
- The paper reports the Spearman correlation across the 14 teachers between the full-gradient and
  LESSER values of each statistic, and the mean over teachers of the Jaccard similarity between the
  two sets of central responses.
- The original analysis stored the exponential of the spectral entropy (the Vendi score); the rank
  correlation is the same.

## Files in `data/grace`

| file | content |
|---|---|
| `scores_gsm8k_llama1b.json` | roster (Hugging Face ids, generation settings), prompt-subset sha256, GRACE settings, and full-gradient and LESSER scores of the 14 teachers, 10 decimals as printed by `run_teacher.sh` |
| `scores_gsm8k_olmo1b.json` | same for the 10 teachers of row 2, full precision |
| `scores_math_llama3b.json` | same for the 10 teachers of row 3, full precision |
| `bank_stats_gsm8k_llama1b.json` | the eight F.4 statistics and the 64 central responses per teacher and feature type, from `score.py bank-stats` on the stored banks, with the sha256 of each bank |
| `MANIFEST.sha256` | sha256 of the files above (`sha256sum -c MANIFEST.sha256` in `data/grace`) |

Each score file records the sha256 of the original score output of the paper run, which is not
distributed. In those outputs, `prod` is the pipeline's name for LESSER features, and
`as_published` means the released GRACE settings.

## Verification record

- Tier 1: all 24 checked values match the paper; the three printed LaTeX rows are identical to the
  rows of Table 12 in the paper source.
- Tier 2 on the stored banks, with the unchanged upstream scorer: the scores match `data/grace` to
  4.9e-11 for row 1, whose reference has 10 decimals, and to 1.2e-16 or better for rows 2 and 3.
  The three scorings take about 1.5 minutes on a CPU.
  The F.4 statistics agree to 1e-15 relative across NumPy 2.1.2 and 2.2.6 and different BLAS
  thread counts. The F.4 correlations and the Jaccard mean equal those of the original analysis
  output to 1e-16, and the exponential of each teacher's spectral entropy equals the Vendi score
  of an earlier analysis to 4e-15 relative.
- Tier 3 was not re-run (GPU). Checked on a CPU: the patch applies to `64fc99a`; the prompt subsets
  regenerate byte for byte; the 4-of-16 subsample rule reproduces every stored scored row of the 14
  GSM8K and 14 MATH response sets; upstream `tokenize_data.py` rebuilds all 49,152 stored tokenized
  rows of the 24 scored sets; the release OLMo script rebuilds the paper's rows and truncations.

## Notes

- In row 1 the two best teachers under LESSER features are 0.1% apart (Qwen2.5-1.5B-Instruct
  0.017572, Qwen2.5-3B-Instruct 0.017590); under full gradients they are 3.4% apart. Table 12
  reports these point estimates.
- Distillation runs (students trained on teacher responses) are not part of the paper and not part
  of this release.
